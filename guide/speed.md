# 怎么做得快

每次工具调用都要等模型想一遍（几秒），**少调一次就快几秒**（参考实测：耗时 85–90% 在模型这边，手机每步约 1–1.5 秒）。不限调用次数，但不做多余的调用。

1. **开头只列一次设备**拿 device id，后面一直用它。
2. 启动 App（包名见 `app:<名>`）后**先看是不是验证页 / 弹窗**，再点首页搜索框搜；不要逛频道，搜到后用**筛选 / 排序**，不要一屏屏滚、不要换很多关键词重搜。
3. **看界面**先读元素、按 ref 点；截图只在需要时用（截图比读元素慢，也更容易点偏）。
4. **动作和「看结果」放在同一次调用里**：点一下 / 滑一下 / 输入之后要看结果的，用批量执行（`mobile_batch_commands`）把这个动作和 `listElementsAtEnd: true` 放在一起，**不要点完再单独调一次读元素**。参考 2026-10-24 复盘：半数以上的步骤是「这一步只点一下、下一步才读」，每多一步就多等一轮模型（约 8 秒）。
   - **一串已知的动作也一次批量执行**：点搜索框 → 输入 → 回车；返回 → 返回 → 点某个 tab；滑两屏再读。每步之后不需要你判断的，就不要拆开
   - 拆开的只有这些：下一步要按这一步读到的内容决定点哪里；结算页之后（不许批量）；验证码；分享面板等旁边挨着危险项、要先截图核对的时候（核对完之后，「点这一下 → 读结果」可以放进同一次批量）
   - 批量执行里不能截图；确实要看图时，批量执行结束后再单独截一次
5. **能同时做的放在同一轮**：几个互不依赖的读取，一轮一起发，不要排成几轮。
6. 不要每点一下都截图确认，只在关键节点看：进了店、加完购物车、到了结算页。
7. **弹窗直接关**：开屏广告、红包 / 金币 / 券弹层、「开启通知」「去评分」「新版本 · 立即升级」——点「跳过」「关闭」「×」「暂不」「以后再说」，**不点「领」「开心收下」「立即领取」「开通」「立即升级」**。
8. 页面切换后元素没变化：等一下再读一次（App 在加载）；还是没进展就换个办法（截图、BACK、换入口），不要原地反复点同一个地方。
